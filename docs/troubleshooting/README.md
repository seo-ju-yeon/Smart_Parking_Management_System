# 트러블슈팅 기록

이 폴더에는 프로젝트를 개선하는 과정에서 실제로 재현한 문제와 원인, 해결 방법, 검증 근거를 기록합니다.

ADR이 여러 대안 중 특정 설계를 선택한 이유를 기록한다면, 트러블슈팅 문서는 발생한 문제를 어떻게 재현하고 원인을 좁혀 해결했는지를 기록합니다.

## 작성 원칙

- 증상, 관찰한 사실, 원인에 대한 판단을 구분합니다.
- 변경 전·후 요청 흐름이나 상태 변화를 구체적으로 기록합니다.
- 코드 확인과 수동 검증을 구분하고, 확인하지 않은 결과는 검증한 것처럼 작성하지 않습니다.
- 문서 번호는 작성 순서를 나타내며 문제의 심각도나 우선순위를 의미하지 않습니다.
