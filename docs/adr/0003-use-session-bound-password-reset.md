# ADR-0003: 세션 기반 비밀번호 재설정 권한 도입

- 상태: 승인

## 상황

기존 비밀번호 찾기는 임시 비밀번호를 데이터베이스에 먼저 저장한 뒤 이메일로 발송했다.
이 방식은 이메일 발송에 실패하면 비밀번호는 이미 변경되었지만 사용자는 임시 비밀번호를 받지 못해 로그인할 수 없는 문제가 있다.
또한 임시 비밀번호를 이메일로 전달하는 것보다 본인 인증을 마친 사용자가 직접 새 비밀번호를 설정하는 방식이 더 명확하다.

## 결정

OTP 인증이 성공하면 임시 비밀번호를 생성하지 않고, 현재 세션에 비밀번호 변경 권한을 부여한다.

세션에는 다음 정보만 저장한다.

- `forgotPasswordResetManagerId`: OTP 인증을 완료한 관리자 아이디
- `forgotPasswordResetGrantedAt`: 비밀번호 변경 권한을 받은 시간

비밀번호 변경 요청에서는 클라이언트가 보낸 관리자 아이디를 신뢰하지 않고 세션의 관리자 아이디를 사용한다.
변경 권한은 5분 동안 한 번만 사용할 수 있으며, 성공 후 즉시 제거한다.
OTP 인증 성공 시 세션 ID를 교체하고, 새로운 OTP 발급이나 인증 흐름 초기화 시 기존 변경 권한도 제거한다.

## 검토한 대안

### 1. 임시 비밀번호를 DB에 저장한 후 이메일 발송

구현은 단순하지만 메일 발송 실패 시 사용자가 변경된 비밀번호를 알 수 없다.

### 2. 이메일 발송 후 임시 비밀번호를 DB에 저장

DB 저장에 실패하면 이메일로 받은 비밀번호와 실제 비밀번호가 달라질 수 있다.

### 3. 실패 시 이전 비밀번호로 복구

보상 처리가 추가되어 흐름이 복잡해지고, 실패 상황을 완전히 처리하기 어렵다.

### 4. 별도의 비밀번호 재설정 링크 발급

확장성과 사용자 경험은 좋지만 토큰 저장, 만료, 링크 위조 방지 등 현재 프로젝트 범위를 넘는 구현이 필요하다.

### 5. OTP 인증 세션에서 사용자가 직접 새 비밀번호 설정

메일 발송과 비밀번호 변경을 분리할 수 있고 현재 세션 구조에서 명확하게 구현할 수 있어 이 방식을 선택했다.

## 결과

- 메일 발송 실패 때문에 사용자가 기존 비밀번호와 새 비밀번호를 모두 사용할 수 없게 되는 상황을 방지한다.
- 인증을 완료한 관리자만 제한된 시간 안에 비밀번호를 변경할 수 있다.
- 관리자 아이디 변조를 통한 다른 계정의 비밀번호 변경을 차단한다.
- 비밀번호는 서버에서 검증한 뒤 BCrypt로 암호화하여 저장한다.
- 현재 방식은 서버 세션에 의존하므로 향후 다중 서버로 확장할 때는 세션 공유 방식이나 일회용 재설정 토큰을 다시 검토해야 한다.

## 검증 근거

| 검증 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 임시 비밀번호 생성·이메일 발송 | 1개 흐름 | 0개 흐름 |
| 비밀번호 변경 권한 유효시간 | 없음 | 5분 |
| 변경 권한 사용 가능 횟수 | 해당 없음 | 1회 |
| 비밀번호 변경 대상 결정 기준 | 요청의 관리자 ID | Session의 인증된 관리자 ID |
| 권한이 없거나 만료된 변경 요청 | 해당 없음 | HTTP 401 |

| 시나리오 | 예상 결과 | 확인 결과 |
| --- | --- | --- |
| OTP 인증 전 비밀번호 변경 요청 | 요청 거부 | 통과 |
| OTP 인증 후 새 비밀번호 설정 | 비밀번호 변경 | 통과 |
| 만료되거나 이미 사용한 변경 권한 재사용 | 요청 거부 | 통과 |
