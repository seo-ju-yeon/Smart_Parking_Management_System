# ADR-0002: 2차 인증 완료 전 보호 경로 접근 차단

- 상태: 승인

## 상황

아이디와 비밀번호를 확인한 직후 세션에 관리자 객체가 저장되지만, 이 시점에는 이메일 OTP 인증이 끝나지 않았다.
기존 필터가 관리자 객체의 존재만 로그인 완료로 판단하면 사용자가 OTP 화면을 거치지 않고 보호된 URL에 직접 접근할 수 있다.
또한 재사용된 세션에 이전 인증 완료 상태가 남아 있으면 새로운 로그인에서도 OTP가 완료된 것으로 잘못 판단될 수 있다.

## 결정

보호 경로의 접근 조건을 다음 두 가지가 모두 충족된 상태로 정의한다.

1. 세션에 로그인한 관리자 정보인 `loginManager`가 존재한다.
2. 2차 인증 완료 상태인 `fullyAuthenticated`가 `true`이다.

이 검증은 공통 필터에서 수행한다. 새로운 1차 로그인이 성공하면 이전의 `fullyAuthenticated` 값을 제거하고, 현재 로그인에 대한 OTP 검증이 성공한 후에만 다시 설정한다.

## 검토한 대안

### 1. 관리자 객체 존재만 확인

구현은 단순하지만 1차 인증만 통과한 사용자도 로그인 완료 사용자로 처리되는 문제가 있다.

### 2. 각 Servlet에서 2차 인증 여부 확인

화면별로 세밀하게 처리할 수 있지만 검증 누락과 중복 코드가 발생하기 쉽다.

### 3. 공통 필터에서 전체 인증 상태 확인

보호 경로의 인증 기준을 한곳에서 일관되게 적용할 수 있어 이 방식을 선택했다.

## 결과

- 1차 인증만 완료한 사용자는 보호 경로에 접근할 수 없다.
- 보호 대상 Servlet마다 같은 인증 검사를 반복하지 않아도 된다.
- 새로운 로그인은 이전 세션의 인증 완료 상태를 재사용하지 않는다.
- 필터의 공개 경로와 정적 리소스 예외 목록을 변경할 때는 보호 대상이 빠지지 않는지 함께 확인해야 한다.

## 확인

- 1차 인증 후 대시보드 URL로 직접 접근했을 때 로그인 화면으로 이동하는지 확인했다.
- OTP 인증까지 완료한 후에는 보호 경로에 정상적으로 접근할 수 있음을 확인했다.
