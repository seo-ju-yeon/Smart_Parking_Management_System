# ADR-003: OTP 인증 후 세션 기반 비밀번호 변경 허가 도입

- 상태: 승인

## 문제 상황

기존 비밀번호 찾기는 이메일 OTP가 일치하면 10자리 임시 비밀번호를 생성하고, DB 비밀번호를 먼저 변경한 뒤 임시 비밀번호를 이메일로 발송했습니다.

메일 발송 중 예외가 발생하면 로그만 기록하고 처리를 종료하지 않았기 때문에 성공 JSON 응답까지 실행됐습니다. 이 경우 기존 비밀번호는 이미 무효화되고, DB에 저장된 임시 비밀번호는 사용자에게 전달되지 않았지만 화면에는 발송 성공 메시지가 표시될 수 있었습니다.

또한 임시 비밀번호 자체가 이메일에 남고, 사용자가 원하는 비밀번호를 직접 설정하려면 임시 비밀번호로 로그인한 뒤 다시 변경해야 했습니다.

## 변경 전 흐름

```text
OTP 인증 성공
→ 10자리 임시 비밀번호 생성
→ DB 비밀번호 변경
→ 임시 비밀번호 이메일 발송 시도
→ 발송 실패 예외는 로그만 기록
→ 성공 JSON 응답 실행
```

메일 발송에 실패하면 기존 비밀번호는 사용할 수 없고, 새 임시 비밀번호는 사용자에게 전달되지 않습니다.

## 결정 기준

- OTP 이메일 발송 실패가 DB 비밀번호 변경으로 이어지지 않아야 합니다.
- 임시 비밀번호를 생성하거나 이메일로 전달하지 않습니다.
- 비밀번호 변경 대상은 OTP 인증 과정에서 서버가 확인한 관리자로 한정합니다.
- OTP 인증 성공 시각부터 5분 동안만 비밀번호 변경을 허용합니다.
- 현재 애플리케이션에는 공유 세션 저장소나 비밀번호 재설정 토큰 테이블이 없으므로 기존 `HttpSession`을 사용합니다.

## 결정

이 문서의 비밀번호 변경 허가는 `NORMAL`, `ADMIN`과 같은 관리자 역할을 의미하지 않습니다. OTP 인증을 완료한 세션에 일시적으로 저장하는 비밀번호 변경 가능 상태를 의미합니다.

OTP 인증 성공 시 비밀번호를 변경하지 않고 다음 두 값을 세션에 저장합니다.

| 세션 속성 | 의미 |
| --- | --- |
| `forgotPasswordResetManagerId` | OTP 인증을 완료한 관리자 아이디 |
| `forgotPasswordResetGrantedAt` | 비밀번호 변경 허가를 저장한 서버 시각 |

`forgotPasswordResetGrantedAt`부터 5분이 지나지 않은 경우에만 변경 요청을 처리합니다. 변경 대상은 요청 파라미터가 아니라 세션의 `forgotPasswordResetManagerId`로 결정합니다.

OTP 인증으로 세션에 비밀번호 변경 허가가 추가되므로 인증 전 세션 ID가 그대로 유지되지 않도록 `changeSessionId()`를 호출합니다.

세션 또는 허가 정보가 없거나, 5분이 지났거나, 대상 계정이 삭제·비활성화된 경우에는 허가 상태를 삭제하고 HTTP 401을 반환합니다. 비밀번호 입력 오류와 일시적인 DB 오류에서는 5분 안에 다시 시도할 수 있도록 허가 상태를 유지합니다.

DB 비밀번호 변경에 성공하면 허가 상태를 삭제합니다. 따라서 성공 처리가 끝난 뒤 같은 세션으로 다시 요청하면 허가 정보가 없어 HTTP 401을 반환합니다.

## 변경 후 흐름

```text
OTP 인증 성공
→ 사용한 OTP 상태 폐기
→ changeSessionId()로 세션 ID 교체
→ 세션에 관리자 ID와 허가 시각 저장
→ 사용자가 새 비밀번호와 확인값 입력
→ 서버가 세션 허가·5분 유효시간·계정 상태·입력값 검증
→ ManagerDAO가 새 비밀번호를 BCrypt로 해싱하여 DB 변경
→ 비밀번호 변경 허가 상태 삭제
```

## 검토한 대안

| 대안 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| DB 변경 후 임시 비밀번호 메일 발송 | 기존 구현을 유지할 수 있음 | 메일 실패 시 기존 비밀번호만 무효화되고 임시 비밀번호는 전달되지 않음 | 제외 |
| 임시 비밀번호 메일 발송 후 DB 변경 | 메일 발송 실패 전에는 DB를 변경하지 않음 | DB 변경이 실패하면 이메일로 안내한 비밀번호와 실제 DB 비밀번호가 달라짐 | 제외 |
| 메일 실패 시 이전 비밀번호 해시 복원 | 기존 비밀번호를 다시 사용할 수 있음 | SMTP는 DB 트랜잭션에 포함되지 않으며 복구 실패와 동시 변경까지 별도로 처리해야 함 | 제외 |
| DB 기반 재설정 토큰 링크 | 세션과 분리된 만료·사용 여부를 DB에서 관리할 수 있음 | 토큰 해시, 만료 시각, 사용 시각을 저장할 테이블과 링크 처리 기능이 추가로 필요함 | 보류 |
| 세션 기반 5분 변경 허가 | 기존 `HttpSession`을 사용하고 OTP 인증 결과를 같은 세션에 연결할 수 있음 | 동일 세션에서만 사용할 수 있고 다중 인스턴스에서는 세션 공유가 필요함 | 채택 |

## 결과

### 기대 효과

- OTP 메일 발송에 실패한 경로에서는 DB 비밀번호를 변경하지 않습니다.
- 임시 비밀번호를 생성하거나 이메일에 남기지 않습니다.
- 사용자가 OTP 인증 후 원하는 새 비밀번호를 직접 설정합니다.
- `/forgot-password/reset`은 관리자 아이디를 요청값으로 받지 않고 세션에 저장된 아이디를 사용합니다.
- 변경 성공 후 허가 상태를 삭제하여 이후 요청의 재사용을 차단합니다.

### 감수한 제약

- OTP를 인증한 것과 동일한 `HttpSession`에서 비밀번호를 변경해야 합니다.
- 허가 상태는 발급 시각부터 5분이 지나면 삭제되며 OTP 인증부터 다시 진행해야 합니다.
- `/forgot-password` GET 요청은 진행 중인 OTP와 변경 허가 상태를 삭제하므로 화면을 새로고침하면 첫 단계로 돌아갑니다.
- 성공 후 허가 상태를 삭제하는 방식이므로 동시에 도착한 복수의 변경 요청을 원자적으로 한 건만 처리하는 기능은 없습니다.
- 여러 서버 인스턴스로 실행하면서 세션을 공유하지 않으면 다른 인스턴스에서 변경 허가 상태를 확인할 수 없습니다.

## 검증

### 코드 확인

#### 변경 전 구현

| 확인 항목 | 변경 전 구현 |
| --- | --- |
| 임시 비밀번호 | 영문 대소문자와 숫자로 구성된 10자리 값 생성 |
| DB와 이메일 처리 순서 | `managerDAO.updatePassword()` 실행 후 이메일 발송 |
| 메일 발송 실패 처리 | 예외 로그 기록 후 성공 JSON 응답 실행 |

#### 변경 후 구현

| 확인 항목 | 변경 후 구현 |
| --- | --- |
| OTP 성공 직후 DB 비밀번호 변경 | 실행하지 않음 |
| 변경 허가 저장값 | 관리자 ID와 서버 발급 시각 2개 |
| 변경 허가 유효시간 | `5 * 60 * 1000L` |
| 변경 대상 | 세션의 `forgotPasswordResetManagerId` |
| 허가 없음·만료·계정 무효 | 허가 상태 삭제 후 HTTP 401 |
| 비밀번호 변경 성공 | BCrypt 해시 저장 후 허가 상태 삭제 |
| 화면 새로고침 | GET 요청에서 OTP와 허가 상태 삭제 |

### 빌드 확인

- Java 17 환경에서 `./gradlew clean war`가 성공했습니다.
- 이 결과는 코드가 컴파일되고 WAR가 생성된다는 의미이며, 비밀번호 변경 흐름은 아래 수동 검증으로 별도 확인했습니다.

### 수동 검증

| 시나리오 | 예상 결과 | 확인 결과 |
| --- | --- | --- |
| OTP 인증 없이 비밀번호 변경 요청 | HTTP 401 | 통과 |
| OTP 인증 후 새 비밀번호 설정 및 로그인 | 변경 성공, 새 비밀번호로 로그인 | 통과 |
| 변경 성공 후 같은 세션에서 변경 요청 재사용 | HTTP 401 | 통과 |

수동 검증 결과: **3/3 통과**

5분 만료 처리는 수동 검증 건수에 포함하지 않았으며, 서버의 경과 시간 비교와 HTTP 401 응답 분기를 코드로 확인했습니다.
